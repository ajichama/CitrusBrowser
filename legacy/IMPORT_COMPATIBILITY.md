# 旧書き出し形式の取込

設定の「インポート/エクスポート」から、利用者が SAF で選んだ書き出しだけを読みます。旧アプリの私有領域、全データ消去、DB ファイルの丸ごと置換は使いません。既存の「復元」入口も、対象と統合方法を確認する同じ画面へ接続しています。これはバックアップ時点への完全な巻き戻しではありません。

対応する文書は旧 `.yuzubackup`、`.yuzudial`、現在の `.citrusbackup`、`.citrusdial`、単独ブックマーク JSON/Netscape HTML、設定 XML、スピードダイヤル SQLite です。旧設定バックアップにスピードダイヤル DB は含まれないため、元アプリで別途書き出します。形式は [元プロジェクトの保存実装](https://github.com/hazuki0x0/YuzuBrowser/tree/dev/legacy/src/main/java/jp/hazuki/yuzubrowser/legacy) と対応する現実装に基づきます。

## 選択と既存データ

全カテゴリは最初は未選択です。プレビューで対応キー・ファイル・項目数と除外数を示し、選んだものだけを適用します。

|カテゴリ|主な形式|統合方法|
|---|---|---|
|設定|`shared_prefs/main_preference.xml`、既知の `app_action1_*/*.dat`|現在存在する型一致キー・既知操作だけを上書き。他のキーは保持|
|検索|`files/searchUrl.json`|既存項目・順序を保持。同じ内容を再利用し、ID 衝突は再採番。取込側の有効な選択 ID を対応付け|
|UA・サイト別設定|`files/ualist_1.dat`、`app_pattern1/url_1.dat`|既存 UA 文字列、同じ種別とパターンを保持。WEB_SETTING は既存優先になる順に追加|
|テーマ|設定内の組込み dark/light 選択|組込み選択だけ適用。外部テーマ資産は元の標準バックアップに含まれないため現在の選択を保持|
|ブックマーク|`app_bookmark1/bookmark1.dat` または Netscape HTML|新フォルダへ追加し、ID は既存と独立して発行|
|スピードダイヤル|`speeddial1.db` v1〜v3|同じ正規化 URL の既存項目・画像を保持し、追加分を末尾へ|
|ユーザースクリプト|`databases/userjs1.db` v1/v2|同じ名前と名前空間の既存コード・有効状態を保持。名前なしはコード完全一致で比較。追加分の有効状態は元の値を保存|
|手書きジェスチャー|`app_gestures1/{0,1}.lib.dat` と同番号の `.list.dat`|線と操作 DB を対として検証。同じ座標列は既存優先、操作行 ID・内部ジェスチャー ID は独立して付け替え|
|後で読む|`app_readItLater/index` と同じ時刻名の保存ページ|索引とページがそろう項目だけを末尾へ追加。同じ時刻・URL は既存を保持し、時刻の衝突は空き番号へ付け替え。ページは新しい名前で置くだけで上書きしない。保存ページは1件64MiB・合計1GiBまで|
|マルチタッチ|`files/multiFingerGes_1.dat`|同じ指の本数・軌跡の既存操作を保持して追加|

内部 BookmarkActivity の `id`、UserScriptEditActivity の編集 ID は、実際に取り込んだ項目の対応表で付け替えます。Intent の selector 内も対象です。対応表がない参照は操作ファイル/パターンから除外し、偶然同じ番号の現データへ結び付けません。`save_bookmark_folder_id` やスクリプト有効設定も依存カテゴリを選ばない場合は現在値を保持します。外部アプリの同名 extra は変更しません。UA の選択は文字列そのものであり、架空の UA ID 対応は作りません。

旧 Google の未編集既定値と旧ページ配色値は、適用後の通常設定読込・検索移行を通します。独自 URL、追加パラメータ、現在の別カテゴリの選択を一般置換しません。

## 対象外と検証上限

履歴、ダウンロード、旧保存先への URI 権限、未知の DB/キー/操作、キャッシュ、Java バイナリは取り込みません。名前付き外部テーマは資産なしでは復元できません。未対応項目と依存未選択の参照は成功件数へ混ぜず除外数で示します。スクリプトはコードを実行せず保存しますが、取込後は通常のスクリプト機能で動くため、信頼する書き出しだけを選択してください。

ZIP は、取り出す既知のファイルを1エントリ32MiB・合計64MiBまでとします。Yuzu の標準バックアップはアプリのデータ領域をまるごと含む（実例で約1万エントリ・圧縮後約235MB・展開後約400MB）ため、ZIP 全体は圧縮後1GiB・65,536エントリ、取り出さないエントリの展開合計は4GiBを上限とします。取り出さないエントリも整合性の確認のため展開しますが、保存しません。名前に「:」を含むエントリは、先頭の区切りでなければ受け付けます（名前のとおりに書き出さないため）。操作設定で付加情報が null の操作は既定値として読み、URL 別設定の空のパターンはその項目だけを除外します（どちらも実際の Yuzu の書き出しにあった形）。中央/ローカル一覧、CRC、重複・絶対・親移動パスを検証します。ディレクトリ名の圧縮 payload も計数して拒否します。SQLite はバージョン、通常 table、必要列、整合性、型・行数を検証し、view/virtual table/trigger を受け付けません。画像は各辺512pxとカテゴリ別の合計画素数を検証します。JSON は階層・項目・容量・重複キーを検証し、現在の JSON が破損している場合に空データ扱いで上書きしません。

手書き形式は [AOSP GestureStore](https://android.googlesource.com/platform/frameworks/base/+/android-6.0.1_r81/core/java/android/gesture/GestureStore.java) v1 の big endian と modified UTF を使います。framework 読込前に最大512 entry・2048 sample・sample当たり16 stroke・stroke当たり4096 point・合計10万 point、座標の有限性、ID 重複、欠損・末尾を検証します。

## 保存失敗・並行変更・強制終了

読取・検証は private staging で完了してから確認画面へ進みます。確認後の適用は画面回転で失わず、適用・復旧は画面終了で中断しません。画面自体を処理に保持しません。

選択した SQLite DB は実ファイルの main に ATTACH し、通常の単一接続トランザクションで統合します。全 DB の journal mode が DELETE/TRUNCATE/PERSIST であることを検査し、WAL を強制変更したり、他の writer の接続を閉じたりしません。SQLite の既存 writer とは通常のロックで競合し、失敗時は中止します。[SQLite の複数 DB 原子性の条件](https://www.sqlite.org/lang_attach.html)を前提にしており、DB・SharedPreferences・JSON 全体の電源断/プロセス強制終了をまたぐ完全原子性は保証しません。

ファイルは AtomicFile で保存し、通常例外時は自分が書いた内容と一致する対象だけを巻き戻します。統合元 bytes と保存直前の旧 hash を照合して検出した並行変更は上書きしません。ただし各既存 manager の全 writer を共通ロックで排他する設計ではなく、照合後の極短い競合窓を含む完全排他は保証しません。原本を保管し、取込中は別画面で設定を変更しないでください。

直前値・対象一覧の退避は最初から `files/import-recovery-UUID` に置きます。成功または復旧成功時だけ削除し、復旧不明・競合・強制終了時は保持します。既存の未完退避を次の取込が自動削除することはありません。復旧を完了できなければ通常の成功通知を出さず、元の書き出しを保持して状態確認する案内を表示します。
