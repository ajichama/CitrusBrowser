# 端末での確認手順

この表は実機確認の予定です。実施済みの結果は[進捗](PROGRESS.md)へ記録します。APKの生成と単体テストだけで、この表を合格にしません。

## 準備

使用端末のOS、Android System WebViewのバージョン、APKのコミットとSHA-256を記録します。デバッグAPKで確認し、同じ署名の既存インストールがある場合は更新インストールで設定・保存データが残ることも確認します。署名が異なるときは、データを削除せず確認方法を相談します。

最初は利用可能な1台で確認し、その後、対応下限API 23と最新OSを含めて範囲を広げます。接続・インストールは端末の所有者が許可した方法で行います。

## 確認項目

| 対象 | 操作 | 確認する結果 |
| --- | --- | --- |
| 起動・更新 | 新しいAPKで起動し、ブックマーク・履歴・購読・設定を開く | クラッシュせず、更新前の保存内容を維持する |
| アイコン・表示領域 | ランチャー、通知、縦横回転、IME表示を確認する | アイコンが適切に表示され、操作部がシステムバーやIMEに隠れない |
| 戻る操作 | 通常ページ、入力欄、ダイアログ、全画面動画で戻る操作を行う | 履歴・ダイアログ・全画面の順序に沿って戻り、終了後のバーと画面点灯設定が戻る |
| ページ配色 | アプリの明暗設定とページ配色を別々に変え、サイト別設定も切り替える | 明色、サイトの暗色、サイト優先の自動暗色が設定に従う。暗色非対応のページをすべて暗くできるとは判定しない |
| 配色変更時の状態 | ページ内入力・JavaScriptの状態を用意して配色を変更する | 不要な再読み込みがなく、入力・ページ状態・履歴を保つ。WebViewの計測テストも端末上で実行する |
| フィルタの手動更新 | 一覧の更新・購読単位の更新を行い、画面を回転・閉じて再表示する | 実際の処理へ再接続し、成功・失敗・取消・スキップを混同しない |
| 永続更新・再試行 | 通信断から復帰し、通常の画面終了・プロセス再生成後の更新も確認する | 再試行後に更新され、画面やActivityを保持しない。OSの「強制停止」は通常のプロセス終了と分けて扱う |
| 更新の競合 | 更新中に購読を無効化・削除・URL変更する | 変更を上書きせず、他の購読や以前の正常キャッシュを壊さない |
| Wi-Fi設定 | Wi-Fi限定設定を変え、Wi-Fiと携帯回線で自動更新を確認する | 自動更新が設定を守る。手動更新の結果も明確に表示される |
| 広告判定 | 画像・script・iframe・不明種別と、第三者・例外ルールをテストページで確認する | 種別限定ルールが他種別へ波及せず、例外とドメイン条件が正しく効く |
| ダウンロード | 通常取得、取消、再開、同名保存、通信断、保存先権限を確認する | 破損や他ジョブの一時ファイル上書きがなく、失敗時に状態が明確に表示される |
| OSS画面 | アプリ内のライセンス画面を開く | 文字化けがなく、WorkManagerと原典由来の通知を表示する |

バックグラウンド処理はOSの制約を受けるため、画面を閉じた直後に必ず実行されることを合格条件にはしません。強制停止中の実行も保証しません。再試行・再起動・設定変更によって、古い要求が削除済みの購読を復活させないことを重視します。

不具合の報告には、再現操作、期待した動作、実際の動作、OSとWebViewのバージョン、APKのコミットを添えます。ログに閲覧URLや認証情報が含まれる場合は、そのまま公開しません。
