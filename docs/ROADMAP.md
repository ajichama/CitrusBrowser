# ロードマップ（要望の候補）

更新日: 2026-11-20。現代のブラウザ（Firefox・Vivaldi・Brave・Chrome 等）との比較調査を元にした、今後の機能の候補です。需要と実装量を見て、着手するかを決めます。調査の詳細は、ローカルのレポート `.agents/handoff/reports/browser-feature-survey-2026-11-20.md` にあります（Git 管理外）。

GitHub の Issue に登録できるようになったら、各項目を Issue へ移します。

## 実装済み（2026-11-20）

- Cookie 同意バナー・迷惑要素のリストを、無効の購読候補として追加
- ページ翻訳の https 化
- ページ情報: 接続（https と証明書の発行者）、このページで遮断した数
- サイト単位のデータ消去（手動、またはタブを閉じたら自動。サイトごとに選択）。実機では未確認

## 候補

| 番号 | 機能 | 内容 | WebView での実現性 | 実装量 | 利便性への影響 |
|---|---|---|---|---|---|
| 4 | HTTPS 優先モード | http のページを https で開き、失敗したら http に戻す | 主文書の URL の書き換えで可（WebView に専用の設定はない） | 中 | 古いサイトで開くのが遅くなる場合がある。初期値はオフを想定 |
| 5 | ピクチャーインピクチャー | 動画の全画面表示から PiP に切り替える | onShowCustomView と Activity の PiP の組み合わせで可 | 小〜中 | なし（利用者の操作で切り替える） |
| 6a | タブのミュート | タブごとに音を消す | WebView の音声ミュート（MUTE_AUDIO 機能）。実機の WebView 157 で対応しているかは未確認 | 小 | なし |
| 6b | メディア通知とバックグラウンド再生 | 通知から再生・停止。画面を消しても再生を続ける | JS で再生状態を拾い、Media3 で通知を出す（条件付きで可） | 中 | 電池の消費が増える。初期値はオフを想定 |
| 8a | プロファイル・プライベートタブの Cookie 分離 | ログイン状態をプロファイルごとに分ける | WebView の MULTI_PROFILE 機能（webkit の版と minSdk の議題に関係する） | 大 | 既存のタブの保存形式に影響する。移行の設計が必要 |
| 8b | タブグループ | タブをまとめて名前を付ける | 可（UI とタブの保存形式の拡張） | 大 | タブの保存形式に版付けが必要。タブの復元を壊さないこと |

ほかの候補（優先度は低め）:

- 未使用タブの自動クローズ
- ページの読み上げ（リーダーモードの本文を TTS で読む）
- PDF の内蔵表示（androidx.pdf は minSdk 28 以上）
- デスクトップ表示時の UA と Client Hints の一致
- ユーザースクリプトの GM_* API
- Dynamic Color の任意適用
- Global Privacy Control（効果は部分的）

## WebView では実現できないもの

- 拡張機能（代わりにユーザースクリプトと、GeckoView の別アプリで対応）
- DNS over HTTPS（OS のプライベート DNS を案内する）
- 任意のサイトのパスキー（Google の承認が必要）
- WebAPK（ショートカットで代替）
- 通信のヘッダーの書き換え（uBO の csp・header の構文も含む）
